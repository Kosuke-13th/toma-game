# 学校ゾンビ脱出ゲーム 設計メモ

最終更新: 2026-09-20

## 1. ゲーム概要
息子さんの高校を舞台にしたゾンビ脱出ゲーム。3人ローカル協力プレイ(パッド3台)。
準備フェーズでバフ・アイテムを獲得し、脱出フェーズでゾンビから逃げながら複数マップを
移動し、最終的な脱出ポイントを目指す。

## 2. フェーズ構成

### ① 準備フェーズ(PrepareScene)
- NPC5人を配置(バフ付与NPC3人、何も渡さないNPC2人)
- 代表者1人が近づいて決定ボタン(初期はスペースキー、将来パッド対応)で会話
- 会話できるのは合計3回まで。3回話すと自動的に脱出フェーズへ遷移
- 獲得したバフは3人プレイヤー共通で適用
- 掴み解除アイテムもNPCから入手可能(バフと同様に会話で獲得する想定。
  バフNPCと兼任か別枠かは未確定 → 要相談)

### ② 脱出フェーズ(マップごとに別シーン)
- 教室・廊下・渡り廊下などのマップが特定地点で接続
- マップ切り替えは「シーン遷移方式」(暗転して切り替え)を採用
- **マップごとに独立したシーンクラスとして実装**(例: ClassroomScene, CorridorScene,
  WalkwayScene)。1マップ=1ファイルとすることで、親子開発時のファイル競合を避ける
- **マップ上の座標(入場位置・出口・脱出ポイント)はTiledのオブジェクトレイヤーで管理する**
  (詳細は §6-2)
- 各マップに合流ポイント(=出口)があり、`alive` 状態のプレイヤー全員が
  矩形内に揃うと次のマップへ移動可能
  - 遷移に必要な人数は、その時点の `alive` 人数(3人中1人が `infected` なら2人、
    2人が `infected` なら1人)
  - 全員が `infected` になった場合は GameOverScene へ
- 最終マップの脱出ポイントに3秒間滞在するとクリア

## 3. プレイヤー仕様
- 3人ローカル協力プレイ。開発中はパッド接続数に応じて1〜3人で可変動作(検証しやすさを担保)
- 個別にHPを保持。全員のHPが0になるまでゲーム続行
- プレイヤーの状態は2種類(状態名は文字列 `'alive'` / `'infected'` で統一):
  - `alive`(生存者): HP > 0
  - `infected`(感染者): HPが0になった状態(= ゾンビ化)
- HPが0になった瞬間に `alive` → `infected` へ切り替わる。`infected` から戻ることはない
  (復活要素なし)
- `infected` のプレイヤー:
  - 操作は完全にAI化
  - 他のゾンビと同様、`alive` のプレイヤーにダメージを与える
  - 合流ポイント判定の必要人数に含めない

## 4. ゾンビ仕様

### 3タイプ(固定ステータス、ダメージ・移動速度が変化点)

| タイプ | 元ネタ | 移動速度 | 通常ダメージ | 出現数の目安 |
|---|---|---|---|---|
| 通常ゾンビ | 生徒 | 基準 | 基準 | 複数体 |
| エリートゾンビ | 運動部生徒 | 速い | やや高い | 複数体 |
| ボスゾンビ | 体育教師 | 最速 | 100(ワンパン即死) | 1マップ1体のみ |

具体的な数値は未確定(要相談)。

### 共通アクション「掴み」
- プレイヤーと接触すると、一定時間(デフォルト3秒、難易度調整用に変数化)その場から
  動けなくなる
- 拘束中はダメージも同時発生。ダメージ量はゾンビタイプごとに異なる
  (通常/エリート/ボスでそれぞれ設定、具体値は未確定)
- 他プレイヤーによる救出なし
- 準備フェーズで入手した掴み解除アイテムがあれば、拘束中にアクションボタンで
  自力脱出可能(1回使い切りの消耗品)
- 掴み解除後は一定時間無敵(この無敵時間も変数化し、後から調整可能に)。
  無限ハメ防止のため、同じゾンビにすぐ再度掴まれることはない
- ボスゾンビに掴まれた場合、ダメージ100により実質即死(意図的な仕様)

## 5. 命名規則
- **フェーズ**(企画用語): 準備フェーズ、脱出フェーズ
- **シーン**(コード上のクラス名): 場所の名前を使う。
  例 `PrepareScene`、`ClassroomScene`、`CorridorScene`、`WalkwayScene`、`GameOverScene`
- **プレイヤー状態**: `alive`(生存者)/ `infected`(感染者)

## 6. 技術構成(ファイル分割方針)
親子開発でのコンフリクトを避けるため、機能ごとにファイルを分割する。

```
/project-root
  index.html
  /src
    main.js           シーン登録のみ
    /core
      InputManager.js   パッド/キーボード入力の抽象化、人数可変対応
      EntityFactory.js  プレイヤー/NPC/ゾンビの生成を一元管理(見た目差し替えの窓口)
      PartyManager.js   3人分のプレイヤー状態(HP、生死、ゾンビ化、所持アイテム)を管理
    /scenes
      PrepareScene.js
      ClassroomScene.js  (今後 CorridorScene.js, WalkwayScene.js 等が追加予定)
      GameOverScene.js
    /data
      npcData.js        NPCデータ(バフ・アイテムの割当含む)
      buffData.js         バフ効果の定義
      zombieData.js      ゾンビ3タイプのステータス定義
  /assets              将来のドット絵・タイルマップ用
    /images
    /tilemaps          マップごとの .json(Tiled出力)
  /docs
    design-memo.md     このファイル
```

### 6-2. Tiledマップのオブジェクト設計
各マップのTiledファイルに、オブジェクトレイヤーを1枚(名前は `objects`)置く。
オブジェクトの識別には `name` を使う(Tiledの版による Type/Class の扱いの違いを避けるため)。

| 用途 | Tiled上の種類 | name | カスタムプロパティ |
|---|---|---|---|
| 入場位置 | ポイント | `entry_○○`(例 `entry_west`) | なし |
| 出口(=合流ポイント) | 矩形 | `exit_○○` | `targetScene`、`targetEntry`(文字列) |
| 最終脱出ポイント | 矩形 | `goal` | なし(最終マップのみ) |
| ゾンビ配置(将来) | ポイント | `zombie_○○` | `zombieType`(名前の空きだけ確保) |

- 入場位置は1点だけ置き、3人分のずらしはコード側で行う
- `targetScene` の値は `main.js` に登録したクラス名と完全一致させる
- `targetEntry` は、行き先マップの `entry_○○` の name と一致させる
- 座標の基準が異なる: Tiledの矩形は左上基準、Phaserの `add.rectangle` は中心基準。
  読み込み時に幅・高さの半分を足す変換が必要
- カスタムプロパティの読み出し形式は、最初の1マップで `console.log` して実データで確認する
- 現行のコード内ゾンビ座標(フェーズ2②)は、Tiled導入時に `zombie_○○` へ移行する

## 7. ビジュアル方針
- キャラクターは Pixel Studio でドット絵作成予定
- マップは Tiled で作成予定
  - ドット絵キャラクターとTiledタイルマップの組み合わせは定番構成であり、
    統一感の違和感は少ない見込み
  - ただし以下の対応が必要:
    - タイルサイズとキャラクターサイズの比率を揃える
      (現状プレイヤーは32×32pxなので、タイル32pxで揃えやすい)
    - `main.js` の `config` に `pixelArt: true` を設定する(**現状未対応**、
      ドット絵・タイルをくっきり表示するために必要)
    - 解像度・カメラズームは整数倍で統一する
- 将来ドット絵に差し替える際は、見た目生成(`add.rectangle` → `add.sprite`)の変更を
  `EntityFactory.js` に集約し、各シーンのコードは変更せずに済む設計にする方針
  (**現状 `EntityFactory.js` は未使用、要修正**)

## 8. 実装の進め方(フェーズ分割)
機能追加のたびに仕様が増えているため、一気に全部作らず、小さいフェーズに分割し、
各フェーズごとに動作確認をしながら進める。

1. ✅ 土台づくり: `InputManager.js`(キーボードのみ、人数可変の仕組みだけ用意) +
   シーン遷移の最小構成(`main.js`, 空の `PrepareScene.js`/`ClassroomScene.js`/`GameOverScene.js`)
   **→ 完了・動作確認済み**
2. 🔶 脱出フェーズの単体動作確認(1人プレイ) **→ 進行中**
   - ① ゾンビなしで移動+脱出ポイント3秒滞在クリア **→ 完了・動作確認済み**
   - ② ゾンビ4体を追加して当たり判定を確認 **→ 実装コード提示済み、動作確認待ち**
3. 準備フェーズの単体動作確認(1人プレイ): NPC5人配置、3回会話で脱出フェーズへ
   自動遷移(バフの中身はダミーでOK)
4. バフ連携確認: 準備フェーズで獲得したバフ(HP増加/速度増加/無敵)が
   脱出フェーズに反映されることを確認
5. ゾンビ3タイプ実装: `zombieData.js` を用意し、通常/エリート/ボスの
   速度・ダメージを反映
6. 掴み仕様実装: 拘束・ダメージ・アイテムによる解除・無敵時間を実装
7. 3人プレイ化: `PartyManager.js` を導入し、複数パッド対応・
   HP0時のゾンビ化・合流ポイント判定を実装
8. 複数マップ接続: Tiledの出口オブジェクト(`targetScene` / `targetEntry`)を使い、
   教室→廊下→渡り廊下のマップ遷移を実装

各フェーズの完了時に動作確認を行ってから次のフェーズに進む。
